# 2. Constraints

> Living document. What the design must work within; the decisions that follow from these are the ADRs. Open questions are marked **[OPEN]** inline.

> **How to fill this in:** Constraints you did not choose: required platforms, languages,
> standards, licenses, team size, deadlines, and the conventions every contributor follows.
> A constraint you *chose* is a decision; record it as an ADR and reference it here. Replace
> each italic prompt with prose and delete this block once the section describes the real
> system. Example:
> [wyrd](https://github.com/getwyrd/wyrd/blob/main/docs/design/architecture/02-constraints.md).

## 2.1 Technical constraints

_Platforms, hardware, runtimes, formats — each with its source (plan, ADR)._

## 2.2 Organizational constraints

_Team size, license, development process, open license questions._

## 2.3 Conventions

_Docs, ADRs, and the rule that security changes update the threat model (§14) in the same PR._
